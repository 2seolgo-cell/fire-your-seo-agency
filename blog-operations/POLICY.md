# 공통 운영 원칙

## 원고·개인정보

- 법률 원고는 내부에서 작성한다. AI는 새 원고, 새 Q&A 답변, 사건 경위, 조력, 결과, 법률적 결론을 만들어 넣지 않는다.
- 담당 변호사의 문체와 사실을 유지한다. AI는 위치·문제·근거·질문 형태의 검수 의견만 제시한다. 재배열·삭제·표현 변경도 변경안 검토와 승인 없이 적용하지 않는다.
- 비공개 사건 정보, 의뢰인·피해자·상대방 식별 정보, 사건번호, 금융·의료 자료, 원본 판결문, 계정 인증정보를 저장하지 않는다. 공개 글에 이미 노출돼 있어도 복제하지 않는다. 여러 단서의 조합으로 재식별될 정보도 제외한다.
- 내부 담당자가 원고를 비식별 처리한 뒤 검수한다. 원고 전문·HTML·RSS 원문·이미지·스크린샷은 저장하지 않는다. 파일명·Git diff·로그·보고서에도 남기지 않는다. 원고는 승인된 내부 보관소에서만 취급한다.
- 저장 허용 범위는 사무소 코드, 비식별 문서 식별자·버전, 공개 글 URL, 식별정보 없는 제목·쟁점 요약, 검수 위치, 공개 근거 URL, 집계 성과다. 원고 위치는 개인정보 없는 참조 ID만 사용한다.
- 민감정보를 발견하면 원문을 인용하지 않고 ‘해당 절 비식별 재검토 필요’로 기록하고 검수를 보류한다. 이미 저장됐다면 Git에 추가하지 않고 담당자에게 알리며 접근 제한·보존 정책에 따른 제거를 요청한다. 잘못 저장된 내용을 Git 기록에 남겨 보존하지 않는다.

## 근거와 관찰

- 법령·판례는 실제 확인한 공식 원문, 적용 시점, 조문·판시 범위만 사용한다. 원문 접근 불가·적용 여부 불명확은 미검증이며 담당 변호사 확인 전 발행 보류다.
- 비공개 사건의 실제 결과는 담당 변호사가 승인된 내부 절차에서 확인한다. 저장소에는 확인 상태·역할·시각만 남기며 사건 자료와 개인 이름을 증빙으로 저장하지 않는다.
- 작성 사실과 검증된 사실을 구분한다. 공개 게시글의 승소 주장은 원본 대조 없이 확정하지 않는다.
- 확인 상태는 `확인`, `미검증`, `접근불가`, `적용제외`로 구분한다. 미관측·미검증을 0이나 실패로 바꾸지 않는다.
- 검색 순위·AI 인용은 실제 질의와 출처 확인 없이 단정하지 않는다. 브랜드 언급, 공식 홈페이지 인용, 해당 블로그 글 인용을 구분한다. 근거 링크만으로 모델 학습·인용 효과를 보장하지 않는다.

## 사무소 분리

- 모든 행의 키는 `office + post_id`다. office는 `seoul` 또는 `gwangju`만 사용한다. 신규 원고도 사무소별 내부 관리 ID를 부여한다.
- URL·프로필·담당자·연락처·실적·승인 기록은 사무소별로 관리한다. 어느 사무소인지 확인되지 않은 글은 등록 보류한다.
- 같은 글을 두 사무소에 중복 성과로 계산하지 않는다. 협업·공유 글은 책임 사무소를 확정하고 다른 사무소에는 참조만 남긴다. 지역명만 바꾼 복제 원고를 만들지 않는다.

## 승인과 실행

상태: `접수 → 검수중 → 내부보완요청 → 법률검토완료 → 사용자승인대기 → 승인 → 실행 → 사후확인`.

보완이 없으면 내부보완요청을 건너뛸 수 있다. 민감정보·법률 근거·결과 미검증은 보류다. 검수 통과는 사용자 승인이 아니다. 사용자 승인은 글·버전·변경 범위·실행 종류(기존 수정/신규 발행)에 한정된다. 버전이나 범위가 바뀌면 재승인한다. 승인자 역할·시각·비식별 참조 ID를 기록하며 채팅 원문을 복사하지 않는다.

계정 작업자는 승인 버전과 에디터 내용을 대조한 뒤 실행한다. 실행 실패는 실행 완료로 표시하지 않는다. 승인 없는 수정·발행·삭제·예약·외부 전송을 금지한다. 이 시스템에는 자동 발행 기능이 없다. Git 커밋·Push는 게시 승인과 별개이며 이번 구축 결과는 GitHub 반영 전에 사용자에게 보여준다.
