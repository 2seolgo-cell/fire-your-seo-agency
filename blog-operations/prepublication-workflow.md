# 발행 전 원고 검수 워크플로

## 입력

사무소 설정, 비식별 원고의 내부 참조 ID·버전, 담당 변호사가 확인할 수 있는 공개 근거. 실제 원고 전문은 저장소에 두지 않는다.

## 절차

1. 해당 사무소 `config.md`의 URL·소속을 확인한다. 미설정이면 검수 양식 준비만 하고 외부 작업은 중단한다. 비식별 원고가 있으면 URL 확정 전에도 내용 검수는 가능하다.
2. 개인정보·사건 비공개 정보 점검을 먼저 수행한다. 의심되면 재인용 없이 내부 비식별 요청 후 보류한다.
3. [검수 양식](templates/prepublication-review.md)을 사무소 폴더에 `review-관리ID-v버전.md`로 복사한다. 사무소·문서 ID·버전을 고정한다.
4. SEO: 원고의 실제 질문 1개, 제목의 정확성·과장·중복, 도입 답변 위치, 소제목의 논리, 관련 글 연결을 평가한다. 검색량·순위는 자료가 없으면 미검증이다.
5. GEO: 주어·적용 조건·기준일이 분명한 문장인지, 사례와 일반 법리가 구별되는지, 법령·판례의 공식 근거가 확인되는지 평가한다. 검수자가 새 답변이나 법률 결론을 보충하지 않는다.
6. NEO: 독자의 실제 문제와 지역의 관련성, 제목·태그 반복, 모바일 문단·표·소제목, 공식 사무소 안내의 일관성을 확인한다. 자사 도메인용 기술 항목은 적용 제외한다.
7. 문체·사건 경위·조력·결과를 바꾸지 않았는지 확인한다. 제목·도입·Q&A가 부족하면 ‘내부 작성자 보완 요청’으로 기록한다. 안전한 위치 참조만 남기고 원문 발췌를 보관하지 않는다.
8. 내부 작성자가 수정하고 담당 변호사가 법률·사건 결과를 확인한다. 불명확한 근거를 삭제·대체할지는 내부에서 결정한다. 새 버전으로 재검수한다.
9. [변경·승인 양식](templates/change-approval.md)에 정확한 버전·변경 범위를 확정한다. 사용자가 승인하기 전에는 에디터 수정·저장·발행하지 않는다.
10. 승인 후 계정 작업자가 적용한다. 모바일 표시, 실제 URL·본문 접근, 링크, 승인 버전 일치를 확인하고 사무소 `changes.md`에 기록한다. 사후 점검은 게시글의 공개 여부를 확인하는 것이며 검색 색인 완료를 뜻하지 않는다.
11. 실행일 D를 기준으로 D+14·D+28 측정 예정일을 입력한다. 캘린더 등록·자동 알림은 별도 작업이며 표에 날짜를 적었다고 예약됐다고 하지 않는다.

## 완료 조건

전체 판정은 통과·보완·보류 중 하나다. 개인정보와 법률 근거·결과 확인의 필수 항목이 미검증이면 통과할 수 없다. 플랫폼 통제 항목의 적용 제외는 실패로 계산하지 않는다. 통과하더라도 외부 실행에는 별도 사용자 승인이 필요하다.
